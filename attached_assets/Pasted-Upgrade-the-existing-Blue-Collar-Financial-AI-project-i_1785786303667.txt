==================================================
SEPARATE PROCESSING PIPELINES
==================================================

Use different processing logic for screenshots, image files, and PDFs.

IMAGE FILES:

- Correct orientation using EXIF data.
- Convert HEIC to PNG or JPEG on the server.
- Resize oversized images while preserving text clarity.
- Improve contrast and sharpness when necessary.
- Preserve the source image for the review screen.
- Detect whether the image contains one document or multiple financial documents.
- If multiple documents are detected in one image, label it “Multiple documents detected” and ask the user to crop or upload each document separately.
- Do not force mixed images into the paystub category.

PDF FILES:

- Do not treat an entire PDF as one screenshot.
- First attempt native PDF text extraction.
- Preserve page numbers and page order.
- If a page contains reliable embedded text, use that text.
- If a page is scanned or has little usable text, render that page as a high-resolution image and analyze it visually.
- Classify and extract each page separately.
- Combine pages only when they clearly belong to the same statement or document.
- Allow users to choose which pages to import.
- Show page-level classifications and confidence scores.
- Support multi-page bank, credit-card, mortgage, loan, investment, retirement, and pay statements.

Saved files and screenshots containing the same information should produce the same confirmed financial values.

==================================================
CONFIDENCE, VALIDATION, AND REVIEW
==================================================

Every extracted field must include:

- field name
- extracted value
- document type
- source filename
- source page number
- confidence score
- original source text or visual region used

Use statuses:

- Needs review
- Confirmed
- Rejected
- Duplicate detected
- Low confidence
- Multiple documents detected
- Unknown

Leave uncertain fields blank instead of guessing.

Show the original document or page beside the extracted fields.

Allow the user to edit:

- document type
- field values
- account name
- category
- source destination

Nothing should update the user’s financial profile until the user taps Confirm.

Validation rules:

- Hours must be between 0 and 168.
- Percentages must be between 0% and 100%.
- APR must be between 0% and 100%.
- Credit limits must be greater than or equal to identified balances.
- Net pay cannot exceed gross pay plus identified non-taxable income.
- Minimum payments cannot be negative.
- Account balances cannot be negative unless the account type permits overdraft or margin.
- Due dates must be valid dates.
- Duplicate accounts must not be created automatically.

Duplicate detection should compare:

- institution
- account type
- last four digits
- balance
- statement date
- loan identifier
- transaction identifier

When a possible duplicate is found, allow the user to:

- update the existing account
- create a new account
- reject the import
